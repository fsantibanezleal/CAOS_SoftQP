# Candidate trial and export document contracts

The candidate broker emits a version-2 trial receipt with the independently observed clock, numeric payload reference and exact frame identifier. Preserve the existing version-1 trial schema and API unchanged. A new schema governs version 2; it validates exact fields, bounded elapsed cost, content-addressed numeric references and the method, seed, frame, phase and repetition tuple. Provenance, custody, correlated clock inequalities and original-space numerical acceptance remain independent semantic checks. Schema validity grants no execution permission.

The candidate export is a separately typed version-1 index over complete status, diagnostic, startup and amortization shards and the two matched hypotheses. It binds the admitted T/N/J, model roster, scope, runtime, request, policy, schedule and durable frontier. Retain exact counts and explicit null estimates on undefined hypotheses. A fixture cannot declare scientific qualification. Qualification additionally requires complete matrix, diagnostics and timing evidence, both qualified hypotheses and all current startup/cohort fields. Legacy excluded export observations without startup fields remain readable as unqualified observations; they cannot become current complete scientific output.

Validate producer documents and independent readback through the same committed schema files, in addition to the existing semantic and live-authority checks. Tests use genuine archived excluded trial/export bytes and self-rehashed field mutations, wrong seeds, invalid warmup repetitions, absent payload identity, false qualification and missing startup evidence. Public examples remain explicitly excluded; no scientific dataset, trained model or new outcome is manufactured for schema tests.
