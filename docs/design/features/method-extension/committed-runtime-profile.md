# Profiles bound to committed source

Status: proposed pre-data profile-factory extension. A profile is source/runtime evidence and never an I1 grant. Existing qualification-snapshot defaults remain distinct from a committed-product-checkout profile.

Extend the existing six-path factory with optional `source_commit`, exactly a forty-character Git commit matching the selected product checkout HEAD. In committed mode enumerate the complete existing scientific scope from that Git object: data-pipeline, contract schemas/examples, accepted contract fixtures and the exact small test-support files currently copied by the factory. Reject symlinks, unsupported Git modes, dirty or untracked files inside those input scopes, unsafe/reparse/linked input paths, a missing scope or HEAD drift. Ignored bytecode is not a source input and cannot enter the guarded import route. Do not inspect or disturb unrelated frontend or another checkout's work.

For every selected file, retrieve the actual Git blob and compare its bytes with the selected checkout. Build the immutable external source snapshot from those verified bytes using exclusive writes. Require exact scope/alphabet equality and recheck HEAD and scope cleanliness after copying. The resulting source inventory is computed from that snapshot. Stamp committed-product-checkout only after all checks, recording the actual commit and a digest of the exact Git-blob/SHA256 inventory. Preserve unchanged public wheel, dependency, license, interpreter, native/source, host module and derived-code admission rules. The factory itself and copied guard/helper files must also match their selected committed blobs in committed mode.

The live verifier's committed-source admission must independently compare every selected source entry with the same Git object and actual checkpoint before numerical import. A self-declared source_kind or clean HEAD alone does not establish committed bytes. Guarded source imports use only the admitted file inventory; extra Python or schema files cannot silently join it. Registered execution still needs independently reviewed profile/source identities and genuine operation-specific I1. Default worktree qualifications cannot be relabeled as committed by an argument or edited stamp.

Allow the fixed excluded fixture route to exercise an already committed profile without claiming scientific authority: both source kinds may run the same closed fixture-only operation, while a registered operation still requires committed source plus genuine I1. The fixture policy, response and summary remain explicitly fixture-only with i1_issued=false. This separates source provenance from execution permission and permits qualification of the exact future registered code before registration.

Controls use a tiny temporary Git repository and actual product-shaped source selections. Verify committed bytes/HEAD/blob inventory, refuse dirty tracked and untracked scientific files and symlinks, reject wrong commit or changed guard/helper bytes, preserve default qualification behavior, and prove caller metadata cannot relabel a worktree snapshot. Source-only controls require no numerical imports or dataset draws. After final source commits, independently qualify the exact resulting real 49-package profile and fixed excluded controls before any genuine scientific registration.
