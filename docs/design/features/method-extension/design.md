## Lossless numeric admission correction (independent U1-01)

All scientific schema `number` fields declare the `lossless-float64` format. The strict schema reader checks finite binary64 conversion and exact equality to the submitted Python numeric value before provenance or certificate admission. In particular, a JSON integer is admitted only if float(value) equals that exact integer; values above2^53 are allowed when exactly representable. Positive zero is canonical. Booleans, nonfinite values, negative zero, lossy integers and conversion overflow refuse as ContractError. Explicit JSON integer metadata (indices, counts, seeds and RNG state) retains its exact integer schema and is not coerced to float64. Existing domain limits still apply.

Producers receive Python binary64 floats or exact integers and never rewrite their numeric values. Consumers parse JSON and require the exact canonical writer bytes, so an alternate decimal token that would round on parsing cannot replace those authoritative bytes. This is the registered submitted-float64 contract, not an exact-decimal input extension. The defensive rational helper enforces the same lossless boundary and converts an admitted integer directly to Fraction, or an admitted binary64 float to its exact dyadic Fraction. It never rounds an integer before proof and uses no tolerance substitution. Original and canonical coefficients, bounds, costs, units, curvature diagnostics, candidate coordinates and certificate anchor/direction all pass the same numeric-schema rule.

The analytic U1-01 witness uses N=2^54, P0, q=(-1,0), equality x1=x2 and upper row N*x1-(N-1)*x2<=1. Its exact finite optimum is -1 at(1,1), and direction(1,1) has forbidden upper recession slope1. The literal coefficient -(N-1) is not representable in binary64; the producer and consumer refuse that input before public status or source admission without rounding or changing its bytes. This local contract regression does not modify the sealed24controls/101diagnostic keys. NC22 retains exact proof acceptance; NC23/NC24 retain exact refusal and reader-only screen-only inconclusive serialization. Scientific inputs, solvers, training and full-scale reader throughput remain outside this correction.

The eleven version1.0.0 schemas are learning-protocol, learning-problem (original plus reversible canonical transform), learning-dataset, learning-split, learning-features, learning-labels, learning-checkpoint, learning-calibration, learning-method-result, learning-evaluation and learning-export-index. Existing18 contracts remain unchanged. New interfaces live in pipeline.learned_comparison.contracts with validate/read/write entry points and frozen boundary values.

Every envelope declares schema_id,version,kind,purpose,state,reason,protocol_id,protocol_sha256,source_lock_sha256,provenance,payload and content_sha256. Scientific available artifacts and contract-fixture provider artifacts are distinct. Missing payload is null with a nonempty reason; no default scientific payload is manufactured. Only explicit fixture admission can consume fixture purpose. Schema-valid missing records can be displayed but cannot satisfy a dependency requiring payload. Partial/training/stale are not available states in U1; later stages must produce a missing record until separately contracted.

content_sha256 is SHA256 of compact sorted-key UTF8/LF JSON of the envelope excluding content_sha256. protocol_sha256 identifies compact canonical protocol payload, avoiding self-reference. File references additionally bind actual full read_bytes SHA256. Public JSON writers emit indented sorted-key UTF8/LF; readers require exact canonical writer bytes, reject duplicate keys and nonfinite/bool numeric coercion. Trust comes from an explicit immutable AdmissionContext: accepted R4 registry/keysets, approved protocol payload, registration and source-lock digests and a sealed source/artifact catalog. A recomputed local content hash cannot authorize a different source or registration. Production protocol admission requires a separately trusted registered receipt; fixture contexts are explicitly non-scientific and never create that receipt.

The independently accepted registry is read-only authority supplied to the module and verified against the exact R4 manifest. Numeric inputs are canonical full symmetric CSC with strictly increasing unique row indices, finite nonzero entries and positive-zero normalization; q/bounds/costs/units have exact declared sizes. Exact rational LDL/diagonal certificates establish PSD/rank. Transform S/A/G is reconstructed algebraically from original data to validate matrices, costs, row ordering and recovery; no numerical solver or scientific input generation runs. Results retain raw original and lifted coordinates. Original objective, repaired dual, H/G/K/F/F_all/D, oracle agreement and peak diagnostics are recomputed. Public unbounded status requires exact rational PSD/anchor/Pd/recession proof, with2^-34false certificates refused.

Features bind actual canonical coefficients, ordered coordinate/node/edge maps and training-only normalizer. MLP14-head inventory and GNN52098-parameter architecture remain fixed. Checkpoint numeric files use little-endian float64 raw arrays with explicit tensor names/shapes/offsets/hashes; executable serializers are excluded. Fixture checkpoint tests may exercise one explicitly named single-head fixture or one graph fixture, with untrained numeric zeros and provider purpose; production requires the complete bundle and real training history. Fixture matrices use an explicit sealed tiny expected keyset; they are never registered primary populations. Production uses all frozen primary keys. Exports are read-only checksummed references and cannot fabricate a missing model/result.

read_artifact checks bytes and cross-boundary dependencies through sealed references; write_artifact first validates then writes only new external files atomically, re-reads with the same consumer and verifies actual file hash. Relative paths forbid drives, URLs, traversal, aliases and symlink/reparse escapes. New files cannot overwrite source/authority; no partial artifact survives refusal. All temporary files stay under the configured E: root. No dependency install, environment admission, solver, dataset generation, training, replay adoption or release is part of this unit.

## Final selected U1 spellings and completeness boundaries

protocol_ref is mandatory on every non-missing non-protocol record and contributes to exact parent provenance. Protocol identity hashes its canonical payload; envelope content identity hashes all envelope fields except its own content_sha256; raw references hash full actual JSON bytes. Trusted context also carries actual source/lock bytes, immutable source-record hashes, expected primary/control/diagnostic keys and independent diagnostic evidence seals. Accepted design is a frozen byte snapshot, not a mutable object supplied by an artifact.

Source records explicitly carry PCG64 state, its hash, origin, entropy and named numeric source parameters; fixture states/parameters are labelled and cannot enter scientific production. Original sparse coefficients, bounds, prices, units, exact curvature certificates and canonical transforms are validated before source identity admission. Separate analytic contract-fixture controls may use the explicit contract-fixture: namespace only in the fixture lane; they add no registered primary or diagnostic keys.

Each checkpoint records initial/latest/best/final role, per-head epoch/best-epoch maps and complete history, immutable initial/best/current numeric arrays, named architecture/parameter offsets/shapes/hashes and local seed rules, AdamW moment coordinate maps and RNG byte receipts. Initial/fixture role cannot qualify scientific public inference. Graph train class statistics and threshold calibration are recomputed from complete source-bound train/calibration labels and supplied probabilities; fit/test roles cannot cross. Opaque provider byte blobs demonstrate numeric serialization only, not a functioning runtime state or trained inference.

Method results retain canonical and original primal/dual coordinates, per-trial native flags, exact original objective components/z/violations/peak values, raw/repaired metrics and every timing phase. Canonical feasibility/stationarity/complementarity and attained auxiliary objective are supplemental; original acceptance remains independently recomputed. Original peak dual recovery uses directional scales. Nonfinite data never become finite accepted metrics. Oracle failures have typed null candidates/metrics and retained reasons. Aggregate status follows oracle-failed,missing,timeout,failed,accuracy-rejected,accepted priority, retaining all seven eligible trial slots.

Evaluation carries complete method/control keys and a separate diagnostic ledger with counts/evidence. Original references cannot be substituted per candidate. Temporal totals use summed frame medians; crossed PCG64 seed/source draw files are read as numeric bytes, reproduced from the registered entropy, and reduced through type7quantiles. This verifies existing receipt mathematics; it does not produce scientific input/training data. Missing draws/diagnostics preserve null/false qualification. Export controls describe only exported regime indices and cannot invent unevaluated values or live execution. A first-generation dataset has null parent_manifest_sha256; unread ancestry is refused. Scientific data refresh/ancestry requires a separately reviewed later protocol.

Final admission choices: primary method results require test split; learned inputs must belong to the selected checkpoint held-out split; paired method/control keys reference identical source-frame bytes. Dataset source-unit slots are unique. Registered rank, pure-L1, graph/equality shape and actual method domains match the accepted semantic row. Zero-timing negative records retain diagnostic_native_flag; screen-only or absent exact proof serializes as inconclusive with reason and never as public unboundedness.

For NC23/NC24, method and diagnostic_native_flag describe the claimed backend under inspection; the registered test target remains the certificate/public-status reader. This permits an honest zero-timing inconclusive record and forces exact-Pd/sign refusal for a public unbounded claim without inventing extra solver runs or diagnostic keys.

Generic JSON number classification includes every exact Python integer, so schema minimum/maximum constraints remain active for integer metadata. Only scientific number fields carry the lossless-float64 format. Python integer parser/formatter limits stay unchanged; exceeding them is a ContractError. The final bounded5000-digit API controls and exact128bit metadata-bound controls enforce these distinctions.
