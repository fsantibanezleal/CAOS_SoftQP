# Held-out evaluation and export design

Status: proposed for independent pre-data review. The scientific campaign has yet to open. This design inherits the accepted R4 semantic matrix, negative controls, keyset inventory and numerical, recovery, timing, learning and protocol specifications.

## Authority and input custody

Add one fixed I1 operation, `evaluate-heldout`. The external supervisor approves two independently pinned canonical documents. The request has only schema, operation and projection identity. The policy binds the exact request digest, committed source, profile, admitted registration/source/dependency/producer locks, protocol, preflight, test phase and its projection/native proof, all three frozen checkpoints per learned method, their calibration receipts, exact diagnostic inventory and fixed external roots. It grants one sequential full projection and a 24-hour deadline. A resume additionally pins the accepted frontier and immutable prior receipts. No user-supplied code, command, method subset, seed list, timing limits or checkpoint selection enters the operation.

An externally pinned committed-source 49-package verifier launches one isolated, no-site, no-bytecode Windows job. The parent reuses actual runtime custody, verifies I1, profile, independently scoped readers and exact artifact bytes before opening numerical test data. The worker uses the fixed `evaluation_worker` entrypoint after measured 600-second full installed/source verification and 180-second cold import; both the process tree and actual loaded module/native origins are checked. The same runtime guard as learning must issue a one-use nested worker capability bound to the exact request, fixed scratch, parent/kernel job, nonce, boot digest, test scope and source. Reuse training custody, not its fit/calibrate route. The producer will provide the fixed product dispatcher. Runtime and authority integrations are root-owned.

Use only a sealed `StreamingPhaseReader(role="test")` and its independently validated native proof. Require exact test projection, source/parent/frame digests and preflight identity, linked to the registered global population manifest but never expose train, validation or calibration frame readers, labels or payload paths. Scope contains the sealed three training-derived numeric bundles per learned method, including fitted normalizer and best parameters, independent train-run/checkpoint digests and checkpoint-specific calibration receipt. Reuse `read_frozen_inference` and the frozen calibration reader. Graph thresholds are exactly the chosen seed-specific threshold; L2WS requires the explicit not-applicable calibration disposition. Missing or failed frozen evidence is an eligible failure, never a reason to refit, select another seed, or make a stratum incompatible. STREAM readers need a fixed raw-input projection accessor which authenticates bytes and references without decoding the physical frame for the child. Canonical reconstruction and parity validators must run inside the timed worker.

The policy lists six ordered per-method-and-seed model dispositions. An independently authorized absent disposition includes its reason and whichever checkpoint/calibration reference exists, if any. It produces the full missing repetition keyset for that eligible seed. The frozen evidence reader for evaluation must verify a calibration receipt and its checkpoint/protocol/population binding without reopening calibration samples. The current calibration reader needs a separate sealed metadata projection for this route. Project exact prefit normalizer bytes with the frozen checkpoint and verify their numeric digest. An absent disposition supplies no permission to open held-out data if the evaluation authority or native test scope is missing.

Carry no factors, workspace or auto-warm state across frames. Only the named previous controls carry accepted vectors or prior raw working-set evidence for contiguous N12 frames, same source/phase/repetition, exact identity map. Frame zero and a successor to a failed frame are cold, the latter flagged. Resume holds exact prior input/accepted vector/working set and durable attempt digest or records an untimed prefix replay solely where the registered policy permits. All attempted original/repaired/raw vectors and side maps retain physical units; independently rerun canonical original-space acceptance H, both K terms, D, F, F_all, G and supplemental peak lambdas/stationarity/complementarity. Never use SDK Boolean acceptance alone. Exact flags are 1 for OSQP/native/Flex, 1 or 2 for DAQP, literal Solved for ElastiQP/Clarabel, PROXQP_SOLVED and PIQP_SOLVED for official counterparts. Verify exact registered settings and unchanged pinned defaults before readiness. Routes which lose status, lift-row/side evidence, settings or omit checks require an exact SDK evidence path or an explicit failure, never fabricated data or a relaxed flag.

For each source, process units lexicographically and source/phase/repetition cyclic order from the normative alphabet and registered entropy [20261105,41110,f,r,u,phase,rep]. Use rotation from the pinned phase convention and retain complete ordered schedule/durable ordinal. All frames of a trajectory run consecutively in that method/seed turn. The parent supplies sealed raw input and preauthenticated linked references. It does not cache numerical reconstruction, lift, graph or features for the timed child. The child starts wall clock before mandatory raw validation, physical/canonical recovery of the problem, lift/graph/features, inference, setup/initialization, all fallback attempts, raw/repaired recovery and original-space acceptance. It stops only after acceptance/rejection is computed; native internal timings, signed interval evidence and monotonic milestones are supplemental. No measured clock stops between retries. Initialize every attempt afresh, with exactly two warmups and five measured repetitions. Save cold process, import, model load and setup evidence separately and produce 1/10/100 amortization from sealed observed durations per the canonical contract, never quickest observed cold trial. The first cold cohort is prospectively keyed. Trigger the external 10-second timeout from the parent's release of a nonce-bound ready gate, reject late success and retain failed lifecycle. The watchdog observes actual kernel job, wall clock and bounded aggregate working set; if native blocks it kills only the owned leaf job. A new admitted leaf may continue next scheduled key, with any restart/cold cost retained. An unresolved started ordinal becomes explicit failed/interrupted, never silently remeasured. If 24 hours or resource limits exhaust, preserve the exact remaining keyset with reason and never claim a full observation.

## Exact output and reader contract

Use versioned streaming containers, separate from existing physical v1 and phase v2 artifacts. A result stream registry binds operation, admitted source/locks/defaults, profile, I1, phase native/model/calibration references and canonical keyset digests. Partition canonical ordered status/repetition and diagnostic NDJSON shards with byte count, SHA, exact keys/order/range, offsets to bounded shared raw numeric blocks and immutable content digests. One physical reference attaches to every method/seed/repetition on the same frame; no replicated matrix or feature payload. For each compatible cell retain all seven expected repetition states, including missing/failure reason, exact observed monotonic times and receipts when available. Incompatible cells have exact registered reason and zero repetitions. Always retain enough raw results and side evidence to recompute numerics. The fixed broker emits a nonce, canonical operation/request/policy/profile/source hashes, PID ownership and independently captured start/end/deadline/exit for each accepted timing observation. Store independent receipt expectations; text fields such as observed=true are not evidence of execution. External append-only custody ledger pins the next ordinal and prior receipt, separate from rollbackable scratch. Atomic spool/rename, verify staged digests and canonical reader admission before advancing; resume checks no gaps, duplicates or substitutions. No training artifact rotation or scientific source regeneration occurs during evaluation. Data and checkpoints have an 8 GiB disk cap, benchmark output has a 4 GiB cap, and the external volume needs at least 20 GiB free at start. Apply the R4 4 GiB evaluation RSS cap to the combined evaluation process tree, with one active numerical worker and one numerical thread. Check live byte budgets, streams/cache capacities, filesystem aliases and cleanup. Fail closed instead of truncating or dropping rows.

Derive ledger keys by streaming exact accepted inventories and semantic matrix, validating each phase and result independently. Diagnostic targets use the 24 frozen controls, 101 target/seed keys and zero timed repetitions, in their external excluded lane. References bind the complete 46,368 independently produced three-backend statuses; each held-out frame requires tight accepted OSQP/Clarabel/PIQP evaluations with recomputed agreement and median objective. Native proof can expose indexed test projection only. Only approved tests use tiny fixture matrices, and incomplete numerical target coverage remains reported. Expected ledger counts cross-check 35,328 method statuses plus 7,488 control statuses, 134,640 measured method repetitions plus 36,760 measured control repetitions, 68,560 warmups. Incompatible or missing flags cannot alter inventory membership. Never resample or replace an oracle failure.

Publish versioned v2-compatible streamed evaluation and export index from independently validated shards. Readers check seal, scope, exact inventory identity, units, native source/report, model references, timing custody and row semantics; compact replay selects only evaluated cases with their declared units. A new stream reader adapter must expose the narrow canonical problem/metric/result validation contracts and shared accumulator without constructing fake v1 artifact references or loading both complete exports and all raw results into memory. Reuse canonical math and bootstrap verification, extracting shared functions in root-owned contracts only after review. Existing readers and historical data stay unchanged. No client/CI/build rerun of scientific work.

For each graph seed, admit test classifications only from the independently linked cold DAQP labels with the registered ambiguity mask and source/frame/node weights. Preserve coverage, class counts, PR/ROC, Brier and ten-bin ECE with nulls where the normative denominators vanish. Test scores never change thresholds, weights or calibration. L2WS retains registered residual, original solution-error and actual injection observations without graph classification metrics. The export records numerical acceptance, each acceleration decision and any undefined metric separately.

At the full eligible schedule the 24-hour bake permits less than 360 ms average per warmup or measured repetition even before cold starts, diagnostics, serialization or receipt verification. The per-trial 10-second cap does not establish bake feasibility. The 4 GiB benchmark budget permits less than 18 KiB per expected warmup or measured repetition even before other files, so raw numeric vectors and repair evidence require measured lossless encoded sizing. Shards may use exact little-endian numeric arrays and reproducible sparse/delta encodings with explicit shape and digest. No lossy precision or exclusion of required evidence to fit. Pre-data engineering controls must measure these overheads and retain all failed/missing keys if the campaign exhausts either cap.

For each eligible source/seed form fifth-sample median as third sorted measured full cost and sum all its frame medians before division by matched cold seed0 totals. Treat eligible seed/family/regime/unit strata exactly as R4; use equal seed and family weights, equal regimes per family, equal units per regime. Any required compatible failure/missing/duplicate/nonfinite or nonpositive cost or oracle failure makes a primary estimate and interval null with failure denominator; qualification false. Separate matrix-wide qualification from the two matched hypotheses. Emit 10,000 raw canonical uint8 draw rows per defined hypothesis: one vector of three seeds across every stratum, then one vector of eight source indices per lexicographic fixed stratum shared across all three seed draws. Use NumPy PCG64 SeedSequence([20261105,41100,0 or 1]), default integer RNG call type and cast after every draw, matching the existing reader byte for byte. Width723 for OSQP (7,230,000 bytes) and587 for DAQP (5,870,000 bytes). Run canonical crossed stratified verification and type7 .0125/.9875 quantiles; lower bound strictly >.10 plus complete numerical scope. Retain negative reversal and digest adversaries.

## Integration gate

Proposed external invocation after real I1 and committed source qualification:
```powershell
& $BasePython -I -S -B "$Profile/verify.py" --evaluate --python $RuntimePython --base-python $BasePython --profile $Profile --expected-profile-sha256 $ProfileSha --source $CommittedProduct --run "$ExternalRunRoot/owned-custody" --request "$Governance/evaluate-request.json" --expected-request-sha256 $RequestSha --policy "$Governance/evaluate-policy.json" --expected-policy-sha256 $PolicySha
```

The product dispatcher and worker, versioned schemas, canonical reader bridge, strict native promotion bridge and runtime capability must be reviewed together. Unknown authority, worktree/test-only profiles, missing test and native projection, altered settings or unsupported SDK routes must refuse before scientific IO. Verify exact method/cold/import custody on excluded controls and independent reader checks first. Paused at design review before producer/schema implementation.

The implemented `EvaluationJournal` holds a separate exclusive lease on the governed frontier, pins the exact schedule ordinal before release, then pins staged terminal bytes before appending them to the receipt stream. Projection authenticates the prefix independently and builds a bounded temporary disk index to join ordered trial receipts to status rows. A power loss after intent never authorizes re-execution. A known staged partial append may resume only with byte-for-byte authenticated completion. An unresolved attempt is explicit interruption. The production broker must implement `require_live()` and `observe_trial(key, ordinal=..., deadline_ns=...)` using the fixed verified worker and independently bound raw phase, model, oracle and supervisor receipts. Its terminal record has `state`, `reason` and optional typed `receipt`. The guardian must enforce both the whole-trial and bake deadlines and seal any missing-input dispositions before a terminal enters the journal.
