# Strict admission at file-population scale

Pre-code interface freeze,2026-11-05. This extends the internal Python admission API only. It changes no JSON field, schema version, scientific number/proof rule, R4 identity, population, expected key or existing public method. Scientific/runtime admission and independent source review remain separate.

## Public interfaces

The existing validate_artifact, read_artifact and write_artifact signatures and Artifact return shape remain supported. A new frozen ReadRequest has path:Path, expected_sha256:str|None=None and usage:Literal[consume,fit,calibrate]=consume. New read_artifacts(requests:Sequence[ReadRequest], context:AdmissionContext)->tuple[Artifact,...] accepts at most256requests per call. Empty requests return an empty tuple. Results preserve input order and every duplicate. A wrong request type/usage/hash, failed dependency, missing file, invalid record or cycle raises ContractError for the entire call; no shortened success list is returned. Reading never writes an artifact. Callers admit larger explicitly enumerated populations in ordered chunks and must account for every requested key/state; chunking is not population validation or a denominator exemption.

## Freshness and snapshot boundary

Every independent public call creates a fresh context-bound session; no semantic success is reused across calls. That session opens/hashes the requested JSON and its actual reachable typed JSON dependencies, numeric sidecars and relevant schemas. It does not open unrelated catalog payloads, numeric files or irrelevant schemas. References still require exact equality with the externally sealed catalog and their actual raw-byte hashes. No stat, timestamp, size or path-only key can authorize reuse. Scientific/source/proof and fit/calibration checks remain unchanged.

A read_artifacts call shares that session across its explicit roots. Bytes retained in the bounded cache are first-read snapshots. Exact references must match the snapshot bytes, not a recomputed local declaration. Cached semantic successes retain their transitive artifact-ID closure; an ancestor intersection refuses before reuse, including a cycle reached through a previously validated node. Usage-specific admission is separate. A context switch cannot reuse another context's session.

The snapshot is not a filesystem-wide atomic transaction. Files are first read at different times. An external writer can mutate a file after its first read; this call can continue to use retained first-read bytes. A later independent call must reopen the reachable file and observe/refuse the change. Eviction can require reopening a file within a batch, and every reopen still verifies sealed expected hashes. Root duplicates and schemas retain first-observed byte identities within the call; a conflicting reread refuses. Callers needing a publication-wide snapshot must provide an immutable external artifact directory and independently sealed context.

## Bounded storage and graph work

Each session uses bounded least-recently-used raw-byte and successful semantic caches, each with at most2048entries and64MiB accounting. Semantic accounting includes retained artifact bytes and transitive-ID closure strings; oversized entries are validated but not cached. Caches are optimization only: eviction never grants admission, and shared subgraphs that remain cached are semantically validated once per usage in that batch. A large graph or oversized artifact may require additional work; no universal positive-model throughput or RSS bound is claimed from fixture IO. Parsed immutable schema validators remain limited to the existing32raw-byte-keyed entries.

The immutable AdmissionContext constructs a normalized lexical input-alias set once from its already sealed catalog metadata. This is O(catalog metadata) setup, with no catalog payload reads. Per-write alias membership is constant-time. Every requested output still undergoes current symlink/junction/root/checkout/existing-file checks; the index cannot authorize traversal or existing-input overwrite. Atomic hard-link publication, prepublication consumer validation, postpublication consumer validation and owned-temporary cleanup remain enforced. Writer validation and its two consumer checks use separate fresh sessions so a dependency change between phases cannot be hidden by reuse.
