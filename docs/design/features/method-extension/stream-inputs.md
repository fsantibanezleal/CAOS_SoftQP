# Factored scientific inputs and streamed features

R4 stores each source's coefficients once, puts changing vectors in separate frame files, and streams normalized inputs. The legacy eleven learning contracts and legacy phase format remain the import and fixture path. Their serialized representations stay readable. The scientific path uses five new prospective v2 artifacts and an explicitly selected v2 phase reader. No campaign is registered by this contract.

## Deterministic fitting and role I/O

The existing ordered Python sum, weight renormalization, population variance and zero-variance rule are preserved. Fitting uses sparse coefficient lookups and thin vector segments shared within each exact source/head, visited in the legacy dataset frame-ID order. These allow one coordinate's ordered summation at a time while retaining sparse factors and per-frame vectors. Whole dense coordinate vectors are transient for one computed feature and never materialized to disk. Compare exact reconstructed canonical problem and MLP/graph fields to the accepted v1 functions, including nontrivial weights and graph mapping.

Preflight seals the root policy, fixture lane, registered identities, exact stored references and fully checked mathematical representation. Single-artifact writers freshly admit the actual staged and final bytes and graph under separate strict reader snapshots. Failed postpublication validation removes only the writer-owned output identity. A v2 phase publication reserves an absent external role directory exclusively and installs its verified manifest atomically after copying. It copies only that role's source/frame/available-label payloads, one source copy per unit and no dense features. Its manifest contains frozen train statistics and only role-local records, original reference metadata and logical feature hashes. Consumers independently obtain the role, preflight and manifest hashes and the fixture policy. The role reader verifies actual local source and frame bytes and their binding on every requested problem or feature, recomputes only the requested feature, checks its sealed logical hash, and never traverses global/held-out file references. Test materialization/open refuses before I/O. Existing explicit root/path/reparse/case checks, transient-manifest custody and no-clobber semantics apply.

Checkpoint verification requires the independently admitted train and validation v2 phase readers and verifies both phase manifest identities, common preflight, actual feature-stream reference and exact population, method/seed and head scope. Numeric, architecture/history, optimizer and RNG rules are shared with v1. The feature stream row topology replaces stored feature-file references. A checkpoint-validation success only admits the typed numeric record. Runtime resumption, scientific training or test access have later gates.

## Exact dense source curvature certificates

The v2 original source carries exact LDL pivot rational text. An original dimension is at most 66. To bound decimal length conservatively, multiply a finite binary64 matrix by 2^1074. Entries are integers of absolute value below 2^2098. Hadamard bounds the k-th leading determinant below 2^B(k), with B(k) = 2098k + ceil(k ceil(log2(k))/2) and B(0)=0. Each positive pivot is the ratio of adjoining leading determinants, with an additional factor 2^1074 in the denominator. Its exact reduced decimal numerator/denominator can therefore use at most ceil(0.302 B(k)) + ceil(0.302 (1074+B(k-1))) + 1 characters. The source schema caps the array at 66 and each rational at 84,000 characters. The runtime checks each tighter position bound and compares exact recomputed text, without parsing submitted arbitrary-length integers or changing the process integer-string digit guard. This contains the full finite-binary64 original dimension domain. The legacy v1 schema pivot bound stays unchanged.

## Limits and acceptance

The exact minimum legacy serialization for 15,456 MLP feature records' mandatory arrays is 23,495,167,136 bytes. The 10,752 N12 frames alone account for 19,666,838,016 bytes. The v2 descriptor stores normalizer arrays once per head and a compact digest row per computed feature. The software fixture gate uses a 32-frame shared-matrix source and independently computed expected problem, MLP and graph values, verifies exact on-disk bytes versus logical hashes and instruments actual phase file opens with the original source root unavailable. It challenges equal-length byte mutations, alternate parents, incompatible role/masks, missing entries, unrelated files and competing publications, plus legacy and v2 checkpoint binding. Report actual stored bytes, logical equality, elapsed time, working set and opens. Full 8-GiB dataset/checkpoint, 8-GiB RSS, 600-second preflight and single-worker production measurements precede scientific release. Scientific generation and training still follow independent I1 registration.
