# Proposed bounded scientific generation dispatcher

The current bootstrap qualifies an excluded software control and has a bounded single-request bridge. The scientific production dispatcher needs separate implementation and review before I1. A process-per-source full scan is unsuitable for the registered inventory.

## Scope

The independently reviewed batch plan binds the complete canonical source-slot roster, the scheduler/producer source digests, the protocol and I1 identity, the runtime profile, the canonical output root, and the ordered raw request and policy digests for each slot. A nominated shard is an exact contiguous projection of that signed roster. Size, wall time, memory and writable disk limits belong to the prior review. The plan's verification compares with the complete expected keyset and requires unique order. A producer's own plan cannot authorize an omitted slot.

The supervisor launches one CPU worker under a Windows Job Object for the entire shard. The worker performs a fresh complete file scan and holds the runtime, base and admitted product source file and directory handles until the shard ends. The fixed import finder and native-module audits remain active. A recovery process must establish new custody. It may reuse only durable verified outputs.

## Per-slot handshake

The supervisor validates the independent plan and ledger, then releases one exact next request and policy pair. The owned worker binds both bytes and the active source/Profile/I1 identities under a new one-use capability. The only callable is the verified generator entrypoint. Before an irreversible generation or publication step, the generator rechecks the capability, exact slot, authority evidence and authorized destination. Capability lookup observes real job membership and process-owned file custody. The capsule closes after that request, even if it raises.

The supervisor enforces the per-slot deadline separately from import and scan time. It checks the output source identity, full frame count and each durable file's raw digest. Each slot gets a terminal accepted, refused, failed or timed-out receipt linked to the preceding verified ledger digest. Existing files, failed outputs and orphaned partial publication remain available for verification. The worker can advance only after the supervisor acknowledges the exact receipt. A failure consumes its required key and cannot trigger a replacement draw.

## Resume and completion

A new owner verifies the externally expected root, all previous receipt bytes, the predecessor chain, the exact completed-key prefix, and the actual durable outputs before I/O for any pending slot. A timeout retains the stopped job's logs and an explicit disposition. Recovery derives the remaining projection from the original plan and verified ledger, and refuses records with unmatched offsets or output paths. The final run records the full expected keyset, every terminal disposition, kept artifacts and any remaining pending keys. The gate requires complete projection, not successful-count aggregation.

This is a design proposal. The current runtime proof does not register a source, produce a scientific draw, permit held-out access, or issue I1.
