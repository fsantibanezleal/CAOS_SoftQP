# Fixed learning-worker runtime handoff

The supervised product worker admits exactly two further operations, `train-model` and `calibrate-model`. A canonical independently expected request names the operation, method, seed and optional exact prior run. The separately expected policy binds the source/runtime profile, legitimate I1 admission, protocol, P1 and current role/native-proof identities, frozen inference or resume identity, nominated external output workspace and artifact accounting roots. The calibration limit comes from the frozen policy resolved by the product, and the fit limit includes elapsed time carried from its approved predecessor.

After the fresh installed-file scan, imported-source checks and live Windows job check, the bootstrap calls the one fixed product entrypoint. Its transient `softqp_runtime_custody` registry binds the outer process ID, job, committed source, profile, request and policy. Only this entrypoint can launch one nested training worker. The leaf command identifies the verified bootstrap and a digest-bound launch descriptor in the fixed per-bundle scratch directory. It conveys no corpus, role, governance or outside-role path. The product parent checks genuine I1 and scoped P1/roles/checkpoint before creating the leaf.

The nested job stays in the outer Windows job. The leaf checks actual process ancestry, independently verifies and holds the exact runtime and worker source, then publishes its owned installed-file observation with the exact nonce. The parent acknowledges that exact digest before any numeric imports. The leaf imports installed SDK packages under the same pinned loader/native rules. Before invoking `training_worker.main_verified`, it validates the digest of `boot.json`, checks the job identity and holds the boot file against writes or replacement. It receives only phase packets and attested numeric checkpoint parts through owned IPC. Before initialization, resume, a model advancement or an output transition, the product protocol obtains a new linked authorization from the held parent after I1 and exact role/scope checks. The leaf rechecks live custody and deadline immediately before acting.

The envelope caps the job at 48 hours and the combined working set at 8 GiB. The leaf has separate limits of 600 seconds for installed-file verification and 180 seconds for cold imports. The product enforces the cumulative fit deadline, frozen calibration limit and data/checkpoint quotas. After worker exit, the parent seals the outputs and the supervisor hashes the fixed completion manifest before accepting the report. Engineering qualification profiles refuse registered dispatch. The production run requires a separately pinned profile with reviewed committed product source and genuine I1.
